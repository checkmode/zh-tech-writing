# 中文技术文档排版细则

这些是默认写法。用户要求、项目现有规范和技术语法优先。只调整自然语言，不改代码、命令、路径、URL、配置键或 API 标识符内部的字符。

## 字符与空格

- 中文与英文或阿拉伯数字之间通常留一个半角空格：`在 Linux 上运行 3 个服务`。中文与数字已有不留空格的统一写法时，可沿用项目规范。
- 英文和数字紧邻中文标点时不额外留空格：`支持 macOS、Linux 和 Windows。` 中文括号的内外两侧也不额外留空格：`缓存（cache）已启用`。
- 正文中的阿拉伯数字和拉丁字母使用半角形式。精确转录的原始材料保留原样；不得把全角化、大小写统一等排版操作应用到技术标识符内部。

## 数值与单位

- 正文中的较大数值可用半角逗号分组，例如 `128,000 次请求`，同类数值保持一致。年份、版本号、端口号、编号及可复制的参数不加分组符，例如 `2026 年`、`8080`、`--limit 128000`。
- 数值与英文单位通常留一个半角空格，例如 `16 GB`、`5 ms`、`25 °C`；百分号和角度符号等依照领域惯例，例如 `20%`、`90°`。不混淆 `bit` 与 `B`、`MB` 与 `MiB`，也不擅自换算原文单位。
- 数值范围用 `～` 或“至”，两端单位或百分号写清，例如 `5 ms～10 ms`、`20%～30%`。负数范围宜写成 `-20 °C 至 -10 °C`，避免连接符与负号混淆。端点是否包含会影响操作时，明确写出包含关系。
- 金额写明币种，例如 `1,200 元人民币`、`1,200 美元`，避免让读者猜测货币符号的含义。日期、时间可能产生歧义时写全年份，并按需要说明时区；机器可读的格式保持原样。

## 数值变化

- “增加了”描述增量，“增加到”描述结果。原值为 50，增加了两倍后是 150，增加到原来的两倍后是 100。为免歧义，优先同时给出起止值。
- “降低了”描述减少的比例，“降低到”描述最终水平。从 100 降低了 20%，结果是 80；降低到原值的 20%，结果是 20。避免“减少两倍”，改写为具体比例或原值的几分之一。
- 百分比与百分点不能互换：从 20% 升到 25%，上升了 5 个百分点，相对增幅为 25%。
- 性能变化写明指标、方向、基准和必要的测量条件。例如，耗时从 10 ms 降到 5 ms，可写“耗时减少 50%”；不要据此笼统写成“性能提升一倍”。无法核实条件时保留待确认项。

## 标点

- 中文正文通常使用 `，。；：？（）“”`；英文整句、代码和技术标识符沿用其原有标点。时间、端口和协议语法保留半角冒号，例如 `08:30`、`127.0.0.1:8766`。
- 句子内部的并列短项用顿号，最后一项可用“和”或“以及”连接；带内部停顿的并列分句可用分号。多个完整意思用句号分开，避免整个段落只用逗号连接。
- 冒号引出解释、定义或列举，作用范围要清楚；说明层次复杂时拆句或改成列表，不连续叠加冒号。
- 中文引号使用 `“”`，内层引号使用 `‘’`；书籍和文章名称使用 `《》`。产品、软件或界面控件名称不因是名称就套用书名号。
- 句内补充说明放在中文圆括号中，句子的结束标点放在右括号之后，例如 `修改随后生效（无需重启）。` 独立成句的括注将结束标点放在括号内。
- 省略号写成 `……`，不与“等”或“等等”重复使用；破折号写成 `——`，只在确有停顿或解释作用时使用。参数前缀、负号和代码中的省略标记保留原样。
- 用陈述语气说明事实和限制，避免连续问号、感叹号或用符号代替条件、原因。

## Markdown 排版

- 段落之间留一个空行，正文段首不加空格或全角缩进。标题与正文、列表或代码块之间留空行；保留列表内代码块所需的缩进。
- 标题结尾通常不用句号、逗号、分号或冒号；问题式标题可以保留问号。不要用加粗段落伪造本应能在目录中定位的章节。
- 加粗用于少量需要快速定位的结论、限制或标签；不要每段都加粗一句话，也不靠密集分隔线、装饰图标或整段加粗制造重点。告警块只用于会影响操作或结果的事项，沿用项目已有格式。
- 列表中的完整句子使用句末标点，短语式条目可省略，同一列表保持一致。不要为统一外观在独立命令或字面值内部补句号。
- 表格适合简短、可对照的内容，长步骤和大段解释放回正文。数值列的单位可写在表头，缺失值与零值要区分，表内的竖线按 Markdown 语法处理。
- 自动排版后检查链接目标、代码围栏、内联代码和表格列是否完整；不要用全局字符替换统一全角、半角或空格。
