# zh-tech-writing

供 AI 使用的中文技术写作 skill，适用于 README、设计说明、接口文档、操作指南和故障排查文档的撰写、改写与审阅。

它要求 AI 根据技术事实和读者任务组织内容，写清条件、操作、原因与结果，并检查套话、重复和模板化表达。用户要求、技术语法和项目既有规范优先。

## 使用

使用时保留 `SKILL.md` 与 `references/` 的相对目录结构。AI 从 `SKILL.md` 读取规则，再按任务读取所需细则。

在已加载此 skill 的环境中，可以在请求里指定 `$zh-tech-writing`。也可以直接要求 AI 先读取 `SKILL.md`，再处理目标文档。

编写新文档时，说明读者、目标和可用材料：

```text
使用 $zh-tech-writing，根据当前源码和现有配置说明，编写 docs/quick-start.md。
读者熟悉 Linux 命令行，但第一次接触本项目。
目标是完成首次启动，并判断服务是否正常运行。
保留必要的前提、命令、预期结果和失败处理；缺少依据的内容标为待确认。
```

改写已有文档时，明确允许修改的范围：

```text
使用 $zh-tech-writing，改写 docs/design.md 中的“重试策略”一节。
删去空泛评价和重复总结，调整解释顺序。
保留接口名称、重试条件、次数和失败行为，不修改其他章节。
```

只需要审阅时，明确要求不改文件：

```text
使用 $zh-tech-writing，审阅 docs/api.md，先不修改文件。
检查读者能否理解接口用途、参数限制和错误处理。
指出具体位置、问题、建议改法及理由。
```

现有文档、相关源码和已核实的运行结果都可以作为写作材料。指定文风时，可提供一份希望沿用的同类文档。

## 处理原则

- 先确定读者已有知识和要完成的任务，再决定需要解释什么、按什么顺序解释。
- 区分实际行为、设计意图和待确认事项，保留命令、数值、条件与限制，不用流畅表述掩盖材料冲突。
- 根据内容选择段落、步骤、表格或图解，不为凑齐章节、条目或固定句式添加内容。
- 按信息是否有用判断套话。删除宣传语和重复结论，保留必要的技术术语、对比、原因和例外；不靠虚构经历、添加口语或故意写错来制造人写的感觉。
- 交付前核对内容与结构，再检查句段表达和排版。示例的预期结果与实际验证结果分开表述。

这些规则用于指导写作和检查成稿，不能替代技术验证。普通聊天、一般技术问答和单句润色不属于默认使用范围。

## 文件说明

| 文件 | 内容 |
| --- | --- |
| `SKILL.md` | AI 的入口：适用范围、写作流程和校对要求 |
| `references/manual-structure.md` | 长文、手册和文档站的内容组织与导航 |
| `references/style-patterns.md` | 套话、重复结构和解释顺序的改写示例 |
| `references/typography.md` | 中英文间距、数值、单位、标点和 Markdown 排版 |
| `references/examples-and-figures.md` | 代码与命令示例的编写、验证，以及图解的表达要求 |
